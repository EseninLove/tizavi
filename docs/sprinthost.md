# Перенос Tizavi на SprintHost

## Подготовленный запуск

Магазин работает через Node.js / Passenger. Фронтенд собирается локально на Node.js 24 (`npm ci`, `npm run build`); серверу не нужны Vite и сборочные зависимости. На проверенном аккаунте SprintHost Node.js 22.9.0.

Отдельный релиз содержит `dist`, `api`, `db`, `src/shared`, `deploy/sprinthost/server.ts`, `vercel.json`. В его корень копируются `deploy/sprinthost/app.cjs`, а также package.json и package-lock.json из `deploy/sprinthost/runtime`. Затем `npm22 ci --omit=dev`. Исходники и секреты размещаются **вне public_html**.

Startup читает `~/.config/tizavi/env.json` (права 600, каталог 700), затем загружает API. Не копировать настройки другого проекта и не выводить этот файл в логи. Нужны существующие DB_URL, BOT_TOKEN, ADMIN_KEY, PAYMENT_SETTINGS_KEY и остальные используемые настройки из Vercel. Ключ PAYMENT_SETTINGS_KEY должен остаться прежним, иначе сохранённые платёжные и почтовые секреты не расшифруются.

Для нового сайта в панели SprintHost создать отдельный домен с действующим HTTPS. Пример `.htaccess` (пути заменить реальными):

```apache
PassengerEnabled on
PassengerAppType node
PassengerStartupFile app.cjs
PassengerAppRoot /home/LOGIN/apps/tizavi/current
PassengerNodejs /usr/local/bin/node22
PassengerAppEnv production
Options -MultiViews
Require all granted
```

Не изменять каталоги и настройки ChalRACE. Перезапускать только магазин через `tmp/restart.txt` в корне его релиза.

## База и переключение — ещё не выполнены

1. Уточнить адрес магазина и доступ к текущей базе/настройкам Vercel.
2. Сделать резервную копию PostgreSQL. При смене сервера БД выполнить пробный импорт и сверить пользователей, заказы, платежи, роли и миграции. Для локальной БД задаются DB_SSL_MODE=local и DB_URL с localhost/127.0.0.1/[::1]. Любой внешний адрес при таком режиме отклоняется; для внешних БД проверка TLS остаётся обязательной.
3. На новом HTTPS-адресе проверить каталог, регистрацию, профиль, роль сотрудника, корзину и тестовую оплату. Проверить реальный IP за Passenger: текущая логика вне Vercel использует адрес сокета; нельзя без проверки включать доверие произвольным forwarded-заголовкам.
4. На время финального копирования БД остановить новые записи; не допускать независимых заказов/платежей в двух базах. Сохранить план отката и копию исходной базы.
5. Обновить PUBLIC_APP_URL и public_url в настройках оплаты, callbacks агрегаторов, адрес Mini App в BotFather и настройки Telegram Login. Проверить Secure-cookie через HTTPS.
6. Переключить собственный домен. Адрес `tizavi-shop.vercel.app` принадлежит Vercel и не переносится на SprintHost: понадобится новый адрес или редирект со старого проекта.
7. Включить резервные копии и наблюдение за ошибками. Удалять прежнее размещение только после проверки реальных сценариев.

Подготовка runtime сама по себе не означает переноса рабочей базы или переключения Telegram.
